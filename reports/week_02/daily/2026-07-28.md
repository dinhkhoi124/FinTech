## Problems and fixes

0. Senior review reproduced a validator correctness defect. Integer `title`,
   empty `approved_by`, compatible-enum but wrong family/product, disconnected or
   non-monotonic planned version chains, and missing hard-negative semantic fields
   all false-passed. Same-intent and overlapping hard-negative mutations failed
   only incidentally through label checks rather than explicit contract checks.
   Root cause: the first validator enforced many contract checks but did not
   execute the JSON Schema or fully mirror several schema, lifecycle, and
   hard-negative invariants.

   Fix: the custom standard-library validator now mirrors the required field,
   enum, family/product, lifecycle-plan, and hard-negative contracts. Exact
   supersession/version/date/status/eligibility chains are required, and the
   first-28 gate counts only fully valid structures. Fourteen focused regression
   tests plus a nine-case mutation run prove the former false-pass cases now
   return `FAIL` with explicit error codes. Lesson: a schema artifact is not
   validation unless it is executed or completely mirrored and mutation-tested.
   The dataset stayed byte-identical and its canonical hash remained frozen.
   Senior review verdict after this correction: `APPROVE_COMMIT`.

1. `py -3.11` was unavailable through the Python Launcher. Used the existing
   locked Python 3.11 semantic environment and documented that command.
2. PowerShell sorting introduced a UTF-8 BOM. The strict loader caught it; the
   dataset was normalized to UTF-8 without BOM and a regression test was added.
3. The first phone-like safety scan included metadata dates and IDs, creating 36
   false positives. The scan was restricted to title/headings/content and the
   full validator then passed.

- Expanded from 28 to 36 only after the first tranche passed full minimum

  mutation tests to keep code synchronized with the schema and related contracts.
